Self-check

What the website thinks needs doing, from its own numbers. It fixes what's safe by itself (restarts, retries, the backup AI model, camera-computer updates and roll-backs) and only suggests anything that could change what gets caught.

The number of things to do for each gym is in the table above. Open a gym to see its list and run its checks.

Self-repair and changes

When something breaks, the website works out why, fixes what is safe to fix, and emails you every time. You can also ask it for a change in plain words. Every code change is tested on a full copy of the website and reviewed before it can ship, goes through GitHub so it can always be undone, and never touches detection, sign-in, encryption, prices or privacy.

Backup

Every record (gyms, settings, alert lists, staff answers, results, logs; not photos) in one file, locked with a password you choose. Without the password nobody can open it, including us. Set BACKUP_PASSWORD on Render to also get one by email every night at 3 AM.

Practice a restore: check a backup file opens

Pick a backup file (from the nightly email or a download) and type its password. It is opened on the website and you see what's inside. Nothing is changed. Do this once a month, so you know the backups work before you need one. Restoring for real: node backup.js restore <file> <password> <folder>, then copy the files into DATA_DIR (Render > Shell).
